# 运行期生成的菜单脚本 —— 静态还原

## 怎么拿到的（全程静态，未执行样本）

1. `lian86.exe` 在 `0x409A1F`(launch_payload) 处把生成的 bat 交给
   `%WINDIR%\Sysnative\cmd /c "<bat> <自身路径>"`；
2. 该 bat 位于 `%TEMP%\<4hex>.tmp\<4hex>.tmp\<4hex>.bat`，647,269 B；
3. 它由两层混淆构成：
   - 第一层：连 `set` 都由 `%comspec:~-14,1%` 这类子串展开拼出；
   - 第二层：`%':~N,1%` / `!':~N,1!` 从 160 字符替换表逐字取（共 59,576 次）；
4. 用自写的 cmd 子集解释器（`tools/cmdsim.py` 思路，见下）按 Windows 语义求值：
   `^` 转义下一个字符、`&`/`&&` 切分、`if..else` 分支、`>>`/`>` 重定向只进内存。
5. 关键坑：首行 `@set '=^">nul` 里的 `>nul` 是**重定向**，变量值其实是 `"`；
   守卫 `if !'! neq "` 因此走 else 分支，不会触发自毁。

自毁链（我们从未执行）：
```
if !'! neq "  ( @echo.>%0 & @shutdown /s /f /t 0 & @exit ) else ( @cls )
```

## 刷机子流程（脚本内文本顺序）

```
询问是否看教程 → 选择含 payload 的文件夹或已解包文件夹
→ 正在识别刷机包的信息 → 识别完毕，确认后继续
→ （检测到已有解包目录时）是否复用
→ 刷机包校验（不通过则"禁止刷入"）
→ 正在多线程解包 payload（失败提示：磁盘空间不足/文件不完整）
→ 解包完毕 → 准备工作完毕
→ 检查分区 → 识别设备平台（"你的设备为：天玑设备" / "高通设备"）
→ 按平台走对应刷写分支
```
