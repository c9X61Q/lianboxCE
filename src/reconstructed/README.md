# 反编译破坏的修复（可编译、可验证）

`src/lian86x86/` 里是 IDA 的原始伪代码。本目录是**修复后的重建版本**：
把反编译造成的破坏逐类修回，并用「能否复现原程序行为」来证明修复正确。

---

## 1. 破坏类型 → 修复手法

| # | 破坏表现（伪代码） | 根因 | 修复 |
|---|---|---|---|
| 1 | `dword_4180A8`、`dword_4180C4`、`dword_4180F0` 等一堆无名整数全局 | 全局符号信息在编译时被剥离 | 按用途命名：`g_base_dir` / `g_sep` / `g_tree`，并给出正确类型 `WCHAR*` / `TREE_ENTRY*` |
| 2 | 指针被降级成 `int` / `_DWORD` | 反编译器缺类型推导 | 全部还原为指针；`lian86.h` 集中声明 |
| 3 | `asc_41702E`、`unk_4170C8` 等符号无内容 | 常量池交叉引用丢失 | 按 VA→文件偏移重读，恢复为字符串常量（`strings.h`），并纠正了「这两块是密文」的误判——它们其实是 **GetProcAddress 用的 API 名表** |
| 4 | 12 字节表项全是裸偏移（`12 * v44 + dword_4180F0 + 4`） | 结构体未识别 | 定义 `TREE_ENTRY { size, path, reserved }` |
| 5 | `*(_DWORD *)(v12[0] + 4 * v13) = (char)*v20++` 之类 | 数组元素宽度丢失 | RC4 的 S/K 盒按「DWORD 存储、低 8 位语义」重建，保留原实现的怪癖 |
| 6 | `do { ... } while (!__OFADD__(1, v13++))` | 编译器溢出标志内建 | 还原为普通 `for` 循环 |
| 7 | `__userpurge sub_405110@<eax>(...)` | 非标准调用约定 | RC4/SHA-1 统一为 `__cdecl`（原为栈传参 + EAX 返回值），去掉 ABI 噪声 |
| 8 | 字符串手术：`sub_4057F0`/`sub_45xx` 层层 append | 内联的 `std::wstring` 操作 | 清单解析重写为 `parse_manifest()`，按 `:` 与 `*` 切分 |
| 9 | 资源枚举被拆成三条不可读回调 | 回调注册被打散 | 合并为 `pe_enum_rcdata()` 显式三层遍历，保留「只认 type 10」语义 |
| 10 | `lpBuffer + 16` 裸偏移读长度 | 容器头未识别 | 定义 `BLOB_HDR { u64 reserved; u64 out_len; }` |
| 11 | 轮常量 `1518500249` | 十六进制被转十进制 | 还原为 `0x5A827999` 等 SHA-1 标准常量 |
| 12 | `v5 ^ v4 & (v6 ^ v5)` | 宏被展开 | 还原为 `Ch(x,y,z)` / `Maj(x,y,z)` / `Parity(x,y,z)` |
| 13 | Linux 下无法编译（`windows.h`） | 目标平台 | 提供 `win32_compat.h` 最小类型层，不模拟行为 |

## 2. 验证（不是"看起来对"，是跑出来一致）

### 2.1 解包器：逐字节复现原程序输出

```bash
./verify.sh /path/to/lian86.exe
```

重建的 `unpack.c` 独立完成：**PE 资源枚举 → RC4 → 16 字节头 → zlib → 按清单落盘**，
输出与 `recovered/tree/` 比对：

```
RT_RCDATA 资源: 34 个
清单条目: 37
落盘 29 个，未匹配 3 个
✔ 全部文件逐字节一致（29 个）
```

「未匹配 3 个」是清单里未引用的重复资源（两份 347831 字节的 busybox、一份 8192 的镜像副本），
不是缺陷——原程序同样不会为它们落盘。

### 2.2 SHA-1：标准向量自检

```bash
gcc -O2 -o selftest selftest.c sha1.c && ./selftest
```

```
sha1(abc)                                          OK
sha1("")                                           OK
sha1(The quick brown fox jumps over the lazy dog)  OK
```

```bash
gcc -O2 -o unpack unpack.c rc4.c -lz
./unpack lian86.exe /tmp/out
```

## 4. 还没重建的部分

已重建的是**安全相关主干**（解包全链路 + 两种密码学原语）。`src/lian86x86/` 里 352 个函数中：

| 类别 | 数量（估） | 状态 |
|---|---|---|
| 解包/密码/IO 主干 | 14 | ✅ 已重建并验证 |
| 字符串与路径工具（`str_append`/`get_short_path`/`w2a`…） | ~120 | 伪代码可读，未重写 |
| 堆/内存池（`sub_40A220`/`sub_40AB74`…） | ~40 | 同上 |
| CRT/编译器内联（`memcpy`/`memset`/SEH） | ~150 | 无重建价值 |
| 其余业务胶水 | ~28 | 同上 |

剩下的不是"修不动"，是改写收益低于阅读收益：伪代码已经能读，
重写成可编译 C 只对需要二改/复现的场景有意义。
